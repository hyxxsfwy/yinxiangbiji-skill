# Obsidian 精选知识库与 LLM Wiki 规则

## 适用场景与核心原则

本规则适用于长期手工维护、后续可接入 AI 半自动整理的 Obsidian 知识库。历史剪藏和大规模自动采集内容继续留在印象笔记；Obsidian 只存持续有用、值得继续使用的内容，不做全量搬运。

文件夹决定“放在哪里”，Properties 决定“它是什么”，标签决定“涉及什么主题”，内部链接决定“与什么知识有关”，书签决定“现在常用什么”，Bases 负责动态汇总。一篇笔记只有一个主要目录和一个主要领域；跨领域关系用内部链接和有限标签表达。目录默认不超过两级业务层级，历史年份不是知识分类，只允许作为精选资料的时间归档。知识地图是人工选择的重要入口，不是文件清单；完整列表交给 Bases 或目录索引。

## 目标目录

```text
@_Obsidian/
├─ 00_首页.md
├─ 01_收件箱/
├─ 10_知识库/
│  ├─ AI/
│  ├─ Quant/
│  ├─ 软件与工程/
│  ├─ 投资理财/
│  └─ 个人成长/
├─ 20_项目/
├─ 30_精选资料/
├─ 90_系统/
└─ 99_归档/
```

`00_首页.md` 是当前入口；`01_收件箱` 用于统一捕获；`10_知识库` 存放长期知识；`20_项目` 存放当前交付材料；`30_精选资料` 存放可引用的原始资料；`90_系统` 存放模板、Bases、附件和 LLM Wiki 资产；`99_归档` 存放不再活跃但需保留引用的内容。当前导出位置和行为保持不变，迁移前须同步调整导出配置并验证图片链接。

## 双层内容

精选资料是仍值得引用、但尚未完全转化为个人知识的原文、网页剪藏、PDF 或参考内容，放入 `30_精选资料`。知识笔记是经过理解、重写、总结、验证或实际使用后形成的个人知识，放入 `10_知识库`；它不复制原文全文，而是通过内部链接引用精选资料。只服务当前交付目标的材料放入 `20_项目`；项目结束后，通用知识提炼进知识库，其余材料归档，不把项目目录变成永久知识分类。

## 迁移判定

仅当以下五项中至少满足两项时，才从印象笔记迁入精选资料：

1. 正在被当前项目使用；
2. 内容仍然有效且不容易重新找到；
3. 能用一句话说明保留价值；
4. 可以关联已有知识笔记或形成新知识笔记；
5. 预计未来会再次引用。

不因“以后可能有用”而迁移。每周历史迁移最多 5 至 10 篇。

## Properties

日常人工维护只要求四个字段：

| 字段 | 允许值 | 说明 |
| --- | --- | --- |
| `type` | `资料`、`知识`、`索引`、`模板` | 内容性质 |
| `domain` | `AI`、`Quant`、`软件工程`、`投资理财`、`个人成长` | 单一主要领域 |
| `status` | `待处理`、`待提炼`、`常青`、`归档` | 内容处理阶段 |
| `tags` | 最多 3 个受控主题标签 | 跨目录主题 |

状态转换为：新捕获内容为 `待处理`；确认保留但尚未消化的资料为 `待提炼`；已形成稳定认识的知识笔记为 `常青`；不再活跃但仍需引用的内容为 `归档`。精选资料完成提炼后转为 `归档`，新知识笔记转为 `常青`。

LLM Wiki 管理字段由模板或自动化维护，允许值与含义如下：

```yaml
uid:
summary:
aliases: []
review_status: pending
reviewed_by:
reviewed_at:
llm_policy: standard
```

`uid` 是不随改名或移动变化的稳定标识；`summary` 是一句话摘要；`aliases` 保存同义名称和旧名称。`review_status` 允许 `pending`、`ai-approved`、`human-approved`、`rejected`；`reviewed_by` 和 `reviewed_at` 记录审批策略和时间；`llm_policy` 允许 `standard`、`strict`、`off`，其中 `off` 禁止 AI 修改。

## 标签

标签只表达主题，不承担来源、领域、类型、状态或优先级。只使用受控主题标签，默认采用 `主题/<主题名>` 两层结构，极少数情况允许第三层。每篇最多 3 个标签；预计至少 3 篇笔记会使用时才创建永久标签。人名、文章名、产品名和一次性概念优先使用内部链接。AI 只能使用主题词表中的标签，新永久标签必须人工审批。

旧标签映射为：`_Apps/微信`、`Twitter`、`微博` 改用 `source` 属性；`$任务/待阅读/+++` 改为 `status: 待提炼`，`$任务/待处理/***` 改为 `status: 待处理`；个人状态标签不进入知识库；`$主题/$网摘` 改为 `type: 资料`，`$主题/$模板` 放入 `90_系统/模板`，`$主题/$资源` 放入 `30_精选资料`；`$个人`、`$学习`、`$工作` 改用 `domain`；`智能体Agent`、`搞懂Agent的第一步` 映射到 `主题/Agent`，`OpenAI开发`、`ChatGPT开发技巧` 映射到 `主题/OpenAI`。

## 首页、书签、Bases 与知识地图

`00_首页.md` 只保留当前入口、知识地图和动态视图，不罗列全部文件。书签分为三个组：`工作台`（首页、收件箱、当前项目）、`知识地图`（AI、Quant 等领域入口）、`动态视图`（待处理、待提炼、近期更新）。普通文章不长期加入书签。

只建立三个 Bases：`全部常青知识.base`（`type = 知识` 且 `status = 常青`）、`待处理与待提炼.base`（`status = 待处理 OR 待提炼`）、`精选资料.base`（`type = 资料`，按领域分组、创建时间倒序）。知识地图只维护核心概念、开发实践、工具平台和待研究问题等人工精选入口，完整文件列表交由 Bases。

## 维护流程

所有新内容先进入 `01_收件箱`，捕获时不设计复杂目录和标签。每周处理时，每篇内容仅四选一：无持续价值则删除或继续留在印象笔记；值得保留原文则移入 `30_精选资料` 并设为 `待提炼`；能形成通用认识则新建知识笔记；只服务当前任务则放入 `20_项目`。每周有限处理，不以清空历史库存为目标。

每月维护：合并同义标签；删除没有继续使用价值的单次标签；更新知识地图人工精选区；归档完成项目；检查收件箱和待提炼队列是否积压；抽查 AI 自动审批结果。

## LLM Wiki

原始资料层正文只读，AI 只能生成摘要、属性和链接建议。知识笔记层允许 AI 补充摘要、别名、受控标签和相关知识，但不得直接删除或改写人工结论。知识地图分为人工保护区和 AI 自动区；AI 只能修改 `<!-- llmwiki:auto:start -->` 与 `<!-- llmwiki:auto:end -->` 标记之间的内容。`llm_policy: strict` 只允许提出建议，`llm_policy: off` 禁止 AI 处理。

每项 AI 变更须经过生成器（提案、证据、目标、置信度）、独立审核模型、确定性校验器（Properties、路径、链接、标签词表、幂等性）和审批策略四个环节。自动审批必须同时满足：操作在人工规则白名单中；存在可定位的证据；只使用已有主题词表；目标链接唯一且无同名歧义；生成器与独立审核模型结论一致；格式、路径、链接和 Properties 校验通过；变更可回滚且写入日志；目标笔记不是 `strict` 或 `off`。任一条件不满足即进入人工队列。

低风险的字段补齐、格式规范、带正文证据且双模型一致的一句话摘要、已有主题标签、唯一内部链接和知识地图 AI 区域更新可自动审批并记录日志；知识笔记草稿可自动生成但保持 `pending`。创建永久标签、修改人工结论、合并、移动、重命名、删除、提升常青状态以及修改人工精选区必须人工审批。

每篇知识笔记默认只保留 3 至 7 个高价值链接：前置或依赖、不同视角、方法与案例、支持补充或冲突观点、原始资料与提炼知识。只出现相同关键词不足以建立链接。

审核资产固定放在：

```text
90_系统/LLM Wiki/
├─ 审核规则.md
├─ 主题词表.md
├─ 别名词典.md
├─ 审核队列/
├─ 审核日志/
└─ 变更快照/
```

人工处理规则冲突、新标签、结构性变更和高风险操作。重复出现的同类审核结果应更新 `审核规则.md`，以便后续自动审批或拒绝。

## 安全边界

AI 不自动删除、移动、重命名、合并文件或创建永久标签；不改写人工结论，也不提升常青状态。找不到唯一链接目标时只生成候选；摘要不能定位原文证据时进入人工队列。自动任务限制单次修改数量，超过阈值分批执行；重复提案不得产生重复标签、链接或地图条目。审批结果必须记录规则版本、模型、证据和变更前后状态；人工可通过 `llm_policy: off` 或保护区域立即停止 AI 修改。真实知识库写入前必须验证路径位于配置的 vault 内。
