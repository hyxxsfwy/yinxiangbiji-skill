# Obsidian 知识管理与 LLM Wiki 规则

## 适用场景与核心原则

本规则适用于长期手工维护、后续可接入 AI 半自动整理的 Obsidian 知识库。历史剪藏和大规模自动采集内容继续留在印象笔记；Obsidian 只保存持续有用、值得继续使用的内容，不做全量搬运。整个 vault 是 LLM Wiki：文件夹表达内容所处阶段，Properties 表达内容性质，标签表达受控主题，内部链接表达经过判断的知识关系。

一篇笔记只有一个主要目录和一个主要领域；跨领域关系使用内部链接和有限标签表达。目录默认不超过两级业务层级，历史年份不是知识分类，只允许作为精选资料的时间归档。知识地图是人工选择的重要入口，不是文件清单；完整列表交给目录索引或 Bases。

`sync_to_obsidian.py` 的全量同步不得写入统一 LLM Wiki 根目录，也不能按印象笔记本名称在生命周期目录旁重新铺设历史目录。`OBSIDIAN_VAULT_PATH` 是正式 Vault 根目录，`YINXIANG_SYNC_VAULT_PATH` 是独立的全量同步暂存目录；两者不能指向同一位置。进入正式 Wiki 的内容必须通过带 `--domain` 的精选导出命令写入明确领域目录。

## Schema 与操作层

Vault 根目录 `AGENTS.md` 是工具中立的行为 Schema，仓库权威模板为 `templates/obsidian-agents.md`。它映射现有生命周期目录，不创建第二套 `raw/` 或 `wiki/`。部署到正式 Vault 前必须获得明确授权。

日常维护使用 Ingest、Query、Lint 三个操作，完整输入、读取顺序、产物、禁止项和完成条件见 `references/llm-wiki-operations.md`。原始资料正文只读；知识草稿保持待审；Lint 默认只读。

## 精选导出的正文领域门禁

搜索关键词只用于产生候选，不代表内容适合目标领域。精选导出必须先从印象笔记 API 拉取完整正文和资源数据，再根据正文主旨判断目标 `domain`；标题、原笔记本、标签和搜索命中只能辅助排序，不能单独授权落盘。

正文判断采用保守门禁：目标领域须有多项可定位的核心或辅助证据，且不能被其他领域明显压过。目标领域证据不足、其他领域占优、多个领域并列或无法确定主领域时均拒绝。拒绝项不写入 Markdown 或附件、不进入目录索引、不占用导出数量，只在命令输出中记录标题、目标领域、判断原因和正文证据。错域内容不自动跨领域搬运，需要用新的目标领域重新审核。

固定执行顺序是：候选合并与排序、拉取完整正文、正文主旨判断、通过项按完全一致标题去重、应用数量限制、写入 Markdown 和附件、重建索引与验证。文件写入是门禁通过后的动作；不得先保存图片或文章再清理错域结果。若最新的同标题剪藏未通过，继续检查较旧版本，以免元数据去重提前丢掉真正匹配的正文。

## 精选资料重分类决策

对已有 `30_精选资料` 做全库重扫时，使用 `reclassify_selected_materials.py` 的 `audit / apply / verify` 主流程；详细命令、decisions 格式和兼容边界见 `references/selected-materials-governance.md`。错域但目标领域明确且值得保留的资料使用 `move`，不属于受管范围或确认无保留价值的资料使用 `trash`，不能形成唯一结论时保持 `pending`，不写入业务变更。旧 `curate_selected_materials.py` 仅用于既有逐篇清单，不承担重扫或跨领域移动。

`10_项目` 只保存有明确目标、交付物和结束条件的工作项目，暂不预建领域目录；实际项目出现后再按项目名建目录。项目完成后，通用认识提炼到 `20_知识笔记`，原始资料进入 `30_精选资料`，其余过程材料进入 `90_归档`。`99_废纸篓`只保存准备删除但仍需短期恢复窗口的内容，不作为长期分类或归档区。

`20_知识笔记` 只有两份根索引：`20_知识笔记/目录索引.md` 与 `20_知识笔记/知识地图.md`。目录索引按 `domain` 分组，列出知识笔记的链接、摘要、状态和更新时间；它可由脚本或 AI 完整重建，不保存人工评语。知识地图不是清单，人工维护核心概念、关键入口和经过判断的关系，AI 只能更新明确证据支持的自动区。

`20_知识笔记` 与 `30_精选资料` 使用固定受管十二领域：AI、Quant、信息技术、投资理财、知识管理、健康医学、中医、两性情感、个人成长、科技产业、自然科学、文史社政。`30_精选资料` 按领域保存原始资料；每个领域保留一份独立的 `目录索引.md`。索引只收录该领域规范 `YYYY年MM月` 目录下 frontmatter 为 `type: 资料` 且 `domain` 与当前领域匹配的文档。资料正文可引用、可追溯，但不自动改写为人工结论。`80_系统/知识库治理` 固定保存审核规则、主题词表、别名词典、审核队列、审核日志和变更快照。

领域边界以正文主旨为准：信息技术覆盖软件工程、项目管理、数据库、容器、存储技术、边缘计算和网络安全；科技产业覆盖芯片、GPU/NPU、光伏、新能源、电车、电池、消费电子与科技公司产业链；自然科学覆盖数学、物理、化学、生物、地理和天文；文史社政覆盖历史、政治、制度、社会结构及公共议题。区块链和加密资产继续归投资理财。“存储”“GPU”“心理”等歧义词不能单独决定目录，必须结合完整正文证据。

## 迁移与验证

已有 Vault 升级固定受管十二领域或执行领域改名时，使用专用命令。`preview` 和 `verify` 对业务资料只读；`apply` 持有独占写锁，为每个实际改动文件保存事务前像，失败时自动恢复。它只执行注册表声明的“软件工程”到“信息技术”、“历史与社会”到“文史社政”，其余既有资料不自动移动：

```powershell
python scripts/migrate_domain_taxonomy.py preview
python scripts/migrate_domain_taxonomy.py apply --confirm EXPAND_MANAGED_DOMAINS
python scripts/migrate_domain_taxonomy.py verify
```

迁移会同步补齐两层十二领域目录、更新精确 frontmatter 与旧目录链接，并全量重建精选资料索引、知识笔记总索引和首页入口。重复 `preview` 的 `change_count` 为 `0` 才满足幂等门禁。

先在本地预览路径映射；预览和验证均只读本地 vault。预览只输出路径映射，不生成清单或链接报告：

```powershell
python scripts/restructure_obsidian_vault.py --vault "D:\OneDrive\文档\@_Obsidian"
python scripts/restructure_obsidian_vault.py --vault "D:\OneDrive\文档\@_Obsidian" --verify
```

仅在用户明确授权后执行迁移：

```powershell
python scripts/restructure_obsidian_vault.py --vault "D:\OneDrive\文档\@_Obsidian" --apply --confirm MIGRATE_OBSIDIAN_VAULT
```

旧 `90_系统`和`99_归档`由重组脚本自动迁移，分别合并到 `80_系统`和`90_归档`；脚本同时创建 `99_废纸篓`。同路径同内容文件会安全合并，同路径异内容或文件类型冲突会在创建迁移写入前中止。

执行前会创建 ZIP 快照，并生成迁移清单和本地链接报告。迁移保留 `30_精选资料/AI/_attachments` 中的图片文件以及文章对图片的相对引用布局，验证阶段会检查这些图片引用可解析。验证失败不会删除旧目录；只有复制、元数据补齐、索引与链接验证均通过后，才清理旧目录；清理失败会从已验证快照恢复旧来源。迁移脚本不会访问印象笔记帐号，也不读取 Developer Token。

## 双层内容与 Properties

精选资料是值得复用、但尚未完全转化为个人知识的原始剪藏、网页、PDF 或参考内容，进入 `30_精选资料`。知识笔记是经过理解、改写、总结、验证或实践后形成的知识，进入 `20_知识笔记`。仅服务当前交付的内容进入 `10_项目`；项目结束后按价值提炼、归档或清理。

日常人工维护固定使用 `type`、`domain`、`status`、`tags` 四个字段。`type` 可为 `资料`、`知识`、`索引` 或 `模板`。`domain` 只可为 AI、Quant、信息技术、投资理财、知识管理、健康医学、中医、两性情感、个人成长、科技产业、自然科学或文史社政；标签只表达主题，每篇笔记最多 3 个受控主题标签。

待审知识草稿默认 `status: 待提炼`，只有人工确认后才可提升为 `status: 常青`。LLM Wiki 附加字段包括 `uid`、`summary`、`aliases`、`review_status`、`reviewed_by`、`reviewed_at` 和 `llm_policy`；`llm_policy: strict` 只允许提出建议，`llm_policy: off` 禁止 AI 处理。

## 旧根标签映射与主题词表

迁移时将旧根标签按四类映射，不把旧目录或标签层级原样复制到新结构：

| 旧根标签类别 | 示例 | 新位置或字段 |
| --- | --- | --- |
| 来源 | `_Apps/微信`、`Twitter`、`微信` | `source` 属性 |
| 状态 | `$稍后/待读/+++`、`$稍后/已读/***` | `status` 属性 |
| 内容类型 | `$笔记/$摘录`、`$笔记/$模板`、`$笔记/$资源` | `type` 属性或对应系统/资料目录 |
| 领域 | `$工作`、`$学习`、`$投资` | `domain` 属性 |

正式主题只有 `主题/Agent`。`主题/OpenAI`、`主题/AI编程`、`主题/AI安全`、`主题/量化研究`、`主题/Codex`、`主题/PKM`、`主题/信息安全`、`主题/区块链` 均为候选主题；候选主题预计至少被三篇笔记复用，并经人工审批后才可转为正式主题。别名和旧称统一在 `80_系统/知识库治理/别名词典.md` 维护。

## 索引、链接与审核

操作日志固定为 `80_系统/知识库治理/审核日志/LLM Wiki 操作日志.md`，只追加时间、操作类型、输入、读取范围、建议写集、实际写集、审核状态和问题数量。

目录索引是可重建的确定性视图，不保存人工评语；知识地图是人工维护核心概念和关系的选择性入口。每篇知识笔记保留 3 至 7 个高价值链接，例如前置或依赖、不同视角、方法与案例、支持或冲突观点、原始资料与提炼知识。仅关键词相同不足以建立关系；同名或多候选链接存在歧义时不得自动审批，进入人工队列。

原始资料正文只读，AI 只能生成摘要、属性和链接建议。知识笔记层允许 AI 补充摘要、别名、受控标签和相关知识，但不得直接删除或改写人工结论。知识地图分为人工保护区和 AI 自动区；AI 只能修改 `<!-- llmwiki:auto:start -->` 与 `<!-- llmwiki:auto:end -->` 标记之间的内容。

自动审批必须同时满足：操作在人工规则白名单中；存在可定位的证据；只使用已有主题词表；目标链接唯一且无同名歧义；生成器与独立审核模型结论一致；格式、路径、链接和 Properties 校验通过；变更可回滚且写入日志；目标笔记不是 `strict` 或 `off`。任一条件不满足即进入人工队列。

低风险的字段补齐、格式规范、带正文证据且双模型一致的一句话摘要、已有主题标签、唯一内部链接和知识地图 AI 区域更新可自动审批并记录日志；知识笔记草稿可自动生成但保持 `pending`。创建永久标签、修改人工结论、合并、移动、重命名、删除、提升常青状态以及修改人工精选区必须人工审批。

## 安全边界

AI 不自动删除、移动、重命名、合并文件或创建永久标签；不改写人工结论，也不提升常青状态。找不到唯一链接目标时只生成候选；摘要不能定位原文证据时进入人工队列。审批结果必须记录规则版本、模型、证据和变更前后状态；人工可通过 `llm_policy: off` 或保护区域立即停止 AI 修改。真实知识库写入前必须验证路径位于配置的 vault 内。
