# 印象笔记精选导出工作流

## 选择导出方式

| 条件 | 工具与模式 |
|---|---|
| 一个目标领域、候选规模可控、需要正文主旨审核 | `export_search_results.py` |
| 两个及以上领域、关键词重叠、要求全量或可能触发限流 | `export_multi_domain.py` 的 `domain_gate` |
| 用户明确要求标题或完整正文命中任一配置关键词即入选 | `export_multi_domain.py` 的 `keyword_union` |

多领域任务不得拆成多个单领域命令后人工合并。运行前用对应脚本的 `--help` 核对当前参数；任务 JSON 从 `templates/` 复制后按本次范围修改，不把某台设备的绝对 Vault 路径写入任务。

## 单领域正文主旨门禁

搜索词只产生候选，标题、笔记本、标签或搜索命中不能授权落盘。处理顺序固定为：

1. 完整分页候选，按 GUID 合并并排序。
2. 拉取完整正文与资源数据。
3. 根据正文主旨判断目标领域；证据不足、其他领域占优、并列或无法确定时拒绝。
4. 通过正文门禁后，按完全一致标题全局去重；依次比较 `updated`、`created`、GUID，保留最新的匹配版本。
5. 最后应用数量限制，只为通过项写入 Markdown、附件和索引。

拒绝项不写入 Markdown 或附件、不进入索引、不占导出名额。最新同标题版本未通过时，应继续审核旧版本，不能用元数据去重提前丢弃可能匹配的正文。错域内容不能自动搬到另一领域，须以新目标领域重新审核。

文章按 `created` 归入 `YYYY年MM月/`；领域根目录保留 `目录索引.md` 与 `_attachments/`。索引包含可打开的位置和非空简介，月度文章中的附件引用必须能解析到实际文件。

## 多领域唯一归属与全局去重

`domain_gate` 对每个 GUID 只审核一次，并统一比较所有已知领域。只有一个领域明显占优时才接受为唯一主领域；并列、证据不足或任务外领域占优均拒绝。历史多领域标签只可作为分析证据，不得代替唯一主领域。

主领域确定后再跨全部目标领域执行全局标题去重。缓存身份是 `GUID + updated + 规则指纹`，与检索关键词无关；规则或更新时间变化时缓存失效。历史目录可以保存摘要、正文哈希、领域证据、唯一主领域、规范路径和审计时间，但不得保存完整正文、附件、Token 或 NoteStore URL。

每个查询项必须分页到服务端总数，不能以候选上限代替全量分页。报告中的 `catalog_hits` 与 `body_requests_saved` 用于说明历史解析复用是否生效。

## `keyword_union` 长期契约

`keyword_union` 面向“标题或完整正文命中任一关键词”的穷尽并集，不使用高精度正文主旨门禁。长期规则如下：

1. 规范关键词、别名、领域顺序和时间范围全部来自本次 UTF-8 任务文件；长期文档不固化日期或关键词清单。
2. 逐项完成搜索分页，按 GUID 合并候选，再对标题和完整正文重新核验。
3. ASCII 字母数字短词使用词边界，文本先按 Unicode NFKC 规范化，避免短词误命中较长单词。
4. 结果归并回规范关键词；各搜索目录的规范关键词命中数量只负责确定候选的初始目录，并列时按任务文件中的目录顺序。最终落盘目录必须再使用与全库重分类相同的九领域标题、正文分类策略判定，不能把搜索目录直接当成知识分类；高置信度结果可以落到任务未声明但属于九个受管领域的目录，分类不充分时才保留初始目录并进入后续审计。
5. 分析写入独立的 `keyword_analyses`，不覆盖正文主旨模式的 `parsed_notes`。缓存包含匹配证据、唯一目录、结果、选择指纹和规范路径，不保存原文或凭据；选择指纹同时包含关键词选择策略和共享九领域分类策略版本，任一策略变化都会使旧缓存失效。
6. 每篇分析先提交状态，再物化 Markdown 与附件；已拒绝项和完整导出项可复用，已接受但文件不完整的项目仅为重新物化请求正文。

中文任务 JSON 必须从 UTF-8 文件加载，不能经 PowerShell 管道或 `python -` 拼接传递。目录迁移遵循先快照、无覆盖原则：同路径异内容立即停止；只有内容哈希一致才能去除旧副本；重建索引并验收后才删除空目录。关键词任务清理非规范旧副本时写入可恢复隔离区；同一来源存在多个不同内容版本时使用内容哈希后缀分别保存，清单按来源和内容哈希保留全部历史，不得覆盖先前隔离版本。重新物化同一篇 Markdown 时必须保留已有的 `llmwiki:auto-links` 受控链接区块，避免印象笔记正文覆盖 Obsidian 内维护的双向链接。

## Vault 状态与续跑

正式 Vault 来自当前设备的 `OBSIDIAN_VAULT_PATH`，同步暂存目录来自 `YINXIANG_SYNC_VAULT_PATH`，二者不得相同。运行状态固定在：

```text
<vault>/.state/yinxiang-notes/export-catalog.sqlite3
<vault>/.state/yinxiang-notes/jobs/
<vault>/.state/yinxiang-notes/runs/
<vault>/.state/yinxiang-notes/reports/
<vault>/.state/yinxiang-notes/single-domain/
<vault>/.state/yinxiang-notes/migrations/
<vault>/.state/yinxiang-notes/active-run.lock
```

旧仓库状态首次迁移时复制并校验哈希，不删除旧状态；目标同名异内容时停止。锁文件不是分布式锁，禁止两台设备同时写同一个 Vault。换设备前必须等待任务结束、SQLite 关闭和 Vault 同步完成。

限流在等待预算内按服务端时长继续。退出码 `75` 表示限流预算耗尽：保留 SQLite、快照、运行状态和已物化文件，稍后用同一任务命令续跑。退出码 `1` 表示业务验收未通过：读取 JSON 报告、修复后续跑，不得改写报告的 `ok`。

## 导出快照自动保留

`keyword_union` 在首次物化前创建 `<16 位任务 ID>-before.zip` 与对应的 `.sha256.json`，并在持有当前 Vault 写锁期间管理这些快照。只有最终完整性验收成功、报告即将以 `ok: true` 落盘且当前 ZIP 的大小和 SHA-256 与清单一致时，才自动清理旧导出快照；默认只保留当前任务的一组完整导出快照。

自动清理只识别直接位于 `.state/yinxiang-notes/snapshots/`、名称严格符合 16 位十六进制任务 ID 且 ZIP 与清单成对存在的普通文件。重分类快照、迁移快照、孤立文件、非法名称、目录和符号链接均不清理；报告、SQLite、运行状态和隔离区不属于快照清理范围。

限流退出、运行异常、验收失败或当前快照校验失败时不清理任何历史快照。成功报告的 `snapshot_cleanup` 记录是否执行、保留的任务 ID、删除文件、释放字节和安全跳过项；若清理本身失败，报告改为 `ok: false` 并记录 `reason: cleanup_failed`，不得把业务写入结束表述为导出完成。

## 完整性门禁

仅当最终 JSON 报告 `ok: true` 且下列项目全部成立时，才能声明完成：

- 每个查询项的拉取数等于服务端总数，候选与分析记录对账成立；
- 每个 GUID 只有一个最终结果和唯一领域或目录；
- 领域内及跨领域重复标题/GUID 为零；
- Markdown 的范围、日期、选择指纹和目录归属符合任务；
- 索引条目都能打开，简介非空，数量与唯一标题和按月统计一致；
- 所有本地附件引用可解析，缺失附件为零；
- 拒绝项没有 Markdown 或附件残留，快照和报告可用于审计与恢复。

进程退出码为零但完整性门禁未通过时，只能报告部分完成。
