# Obsidian 固定受管领域精简扩展设计

## 背景

当前知识库对“固定受管领域”存在三套不一致事实：治理文档与精选资料重分类工具支持九领域，单领域导出器和目录脚手架只支持其中五个，正式 Vault 的 `20_知识笔记` 还缺少“知识管理”和“健康医学”两个既有目录。本次依据用户给出的关键词集合补足明显缺口，同时保持领域数量克制，避免形成稀疏、重叠且难以长期维护的目录树。

## 目标与非目标

本次完成以下目标：

1. 将固定受管领域从九个扩展为十二个；
2. 将“软件工程”重命名为覆盖范围更广的“信息技术”；
3. 让 `20_知识笔记`、`30_精选资料`、分类器、导出器、脚手架、索引、首页、模板、文档和测试使用同一领域契约；
4. 在正式 Vault 中安全完成目录重命名、frontmatter 与内部链接修正、缺失目录补齐和索引重建；
5. 对其余既有资料仅生成十二领域体系下的只读审计建议，不自动跨领域移动。

本次不批量重分类既有资料，不为新增领域强行填充内容，不创建新的永久主题标签，也不改写资料正文中的人工结论。

## 固定受管十二领域契约

固定顺序为：

1. AI
2. Quant
3. 信息技术
4. 投资理财
5. 知识管理
6. 健康医学
7. 中医
8. 两性情感
9. 个人成长
10. 科技产业
11. 自然科学
12. 历史与社会

新增领域边界如下：

| 领域 | 主要范围 | 明确排除 |
| --- | --- | --- |
| 信息技术 | 软件工程、项目管理、编程、数据库、存储技术、容器、云原生、边缘计算、网络与信息安全 | 模型与智能体归 AI；公司与产业分析归科技产业 |
| 科技产业 | 芯片、GPU、NPU、光伏、新能源、电车、电池、消费电子、科技公司及产业链 | 具体软件实现归信息技术；模型训练与推理归 AI |
| 自然科学 | 数学、物理、化学、生物、地理、天文及科学方法 | 医疗实践归健康医学；中医理论归中医 |
| 历史与社会 | 历史、政治、制度、社会结构、中产、女权和公共议题 | 亲密关系实践归两性情感；自我发展归个人成长 |

区块链、BTC、ETH、SOL、TRX、USDT 继续归“投资理财”；心理、恋爱、婚姻和幸福根据正文主旨归“两性情感”或“个人成长”。“存储”“GPU”等歧义词不能单独决定领域，必须结合完整正文主旨和其他证据。

## 单一领域注册表

新增 `scripts/domain_taxonomy.py` 作为唯一领域事实源，提供：

- 有序领域名称；
- 领域说明和核心、辅助证据词；
- 旧名称“软件工程”到“信息技术”的迁移映射；
- 面向命令行、脚手架和文档测试的稳定读取接口；
- 注册表完整性校验，包括领域键集合、顺序、别名唯一性和必需字段。

`export_search_results.py`、`reclassify_selected_materials.py` 和 `restructure_obsidian_vault.py` 不再各自维护领域名称集合。分类算法可保留不同阈值与标题回退策略，但必须消费同一注册表，并由测试保证两个分类入口支持的领域集合完全一致。`export_multi_domain.py` 继续从单领域导出模块取得领域契约，因此任务校验、规则指纹和已有 Vault 扫描会自动覆盖十二领域。

## 正式 Vault 迁移

新增专用命令 `scripts/migrate_domain_taxonomy.py`，提供 `preview`、`apply`、`verify` 三个阶段。该命令只处理本次领域契约变更，不复用一次性的旧 Vault 重组逻辑。

### 预检与预览

`preview` 只读执行并生成确定性计划：

- 验证 Vault 根目录及 `20_知识笔记`、`30_精选资料`；
- 枚举两个“软件工程”源目录、可能存在的“信息技术”目标目录及冲突；
- 枚举需要更新 frontmatter 或内部链接的 Markdown；
- 列出需要创建的缺失领域目录和精选资料索引；
- 确认所有解析后路径仍位于正式 Vault 内；
- 对既有精选资料运行完整性扫描，建立迁移前基线。

任何同名异内容、目标为错误文件类型、无法解析的 frontmatter、非法路径或迁移前完整性错误都会阻止 `apply`。

### 应用

`apply` 必须持有 Vault 写锁，并要求精确确认词 `EXPAND_MANAGED_DOMAINS`。写入前创建增量事务快照，记录修改文件的原始内容、目录移动关系、新增路径和索引数据库备份；快照与凭据均不进入 Git。

应用顺序固定为：

1. 建立事务和写入锁；
2. 将两层中的“软件工程”安全合并或重命名为“信息技术”；
3. 只把原 `domain: 软件工程` 改为 `domain: 信息技术`；
4. 修正精确指向旧目录的 Markdown 链接和 Wikilink，不做模糊正文替换；
5. 在两层补齐全部十二个领域目录；
6. 为十二个精选资料领域重建 `目录索引.md`，并重建知识笔记总索引和首页领域入口；
7. 运行完整验证后提交事务；验证失败则按事务记录恢复。

目录移动保留 `_attachments` 及相对引用布局。除“软件工程”重命名外，不移动其他资料，不修改其主要领域。

### 验证与幂等性

`verify` 必须独立确认：

- 两层目录集合都精确等于十二领域；
- 不再存在受管的“软件工程”目录或 `domain: 软件工程`；
- 十二个精选资料索引与实际规范 Markdown 集合完全一致；
- 知识笔记总索引和首页包含十二领域且不存在旧路径；
- 无缺失附件、断链、跨领域 GUID/标题重复、frontmatter/domain 错误；
- 再次执行 `preview` 不产生业务变更，证明迁移幂等。

## 既有资料只读审计

迁移通过后，使用重分类工具按十二领域重新扫描 `30_精选资料`。审计报告可以给出 `keep`、建议目标领域或 `unclassified` 及证据，但本次不生成或应用 `moves`、`trash`。新增领域为空是合法状态；审计结果只作为后续人工治理输入。

## 文档和模板

同步更新：

- `SKILL.md` 的受管领域与执行边界；
- `references/obsidian-knowledge-management.md` 的目录树、领域说明和允许值；
- `references/selected-materials-governance.md` 的受管范围；
- 关键词并集任务模板，使用户给出的关键词按十二领域归组；
- 首页、索引和命令帮助中的旧领域名称。

现有 `SKILL.md` 中与 Developer Token 预检相关的未提交用户修改必须保留，提交时不得无意扩大暂存范围。

## 测试与验收

实现采用测试先行。至少覆盖：

1. 注册表精确包含十二领域，旧名称仅作为迁移别名；
2. 三个主要入口消费同一领域集合，命令行接受新增领域并拒绝未知领域；
3. 信息技术、科技产业、自然科学、历史与社会的典型正文能形成唯一主领域；
4. “存储”“GPU”“心理”等歧义样例不会只凭单词误分类；
5. 空 Vault 脚手架创建两层十二领域和正确首页、索引；
6. 迁移预览只读，冲突和非法 frontmatter 会在快照前失败；
7. 应用能重命名目录、更新 frontmatter 与精确链接并保留附件；
8. 验证失败能够回滚，重复执行保持幂等；
9. 其余既有资料没有自动跨领域移动；
10. 文档和模板不再宣称固定九领域或把“软件工程”列为当前领域。

仓库验收运行完整单元测试、Python 编译检查和 `git diff --check`。正式 Vault 验收运行专用 `verify`、全领域完整性扫描和 Markdown-only Git 校验；只有全部结果为真才报告完成。
