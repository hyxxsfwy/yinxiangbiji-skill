# 导出快照自动保留设计

## 目标

关键词并集导出在完整性验收成功后，自动清理历史大型导出快照，只保留当前任务的完整回滚快照，避免 `<vault>/.state/yinxiang-notes/snapshots/` 持续增长。

## 范围

自动清理只管理文件名符合下列格式的成对文件：

```text
<16 位十六进制任务 ID>-before.zip
<16 位十六进制任务 ID>-before.sha256.json
```

重分类、迁移等其他工作流的快照不属于本策略。报告、运行状态、SQLite、隔离区和不完整或无法识别的快照均不删除。

## 执行时机

关键词并集导出持有 Vault 写锁期间，先创建当前任务快照并完成业务写入、索引重建和完整性验收。仅当最终报告满足 `ok: true`，且当前快照 ZIP 与清单通过哈希和大小校验后，才执行历史快照清理。

限流退出、运行异常、验收失败或当前快照校验失败时不清理，以保证同一任务能够继续运行或回滚。

## 保留与删除规则

默认保留数量为一组，当前任务快照始终属于保留集合。清理器只删除其他任务 ID 对应、且 ZIP 与清单同时存在的历史导出快照。

遇到孤立文件、目录、符号链接、非法名称或路径越界时，清理器保留目标并记录跳过原因。删除目标必须逐项解析并确认直接位于当前 Vault 的快照目录内。

## 报告

导出报告增加 `snapshot_cleanup` 字段，至少记录：

- 是否执行；
- 保留的快照任务 ID；
- 已删除文件及释放字节数；
- 因安全条件未满足而跳过的项目和原因。

清理失败不能伪装成导出成功。若删除过程中发生异常，导出返回失败并保留已写报告和当前快照，供人工核查。

## 测试

自动化测试覆盖：

1. 成功验收后只保留当前完整快照；
2. 验收失败时不删除任何历史快照；
3. 重分类快照、孤立文件和非法名称不被删除；
4. 当前快照损坏时拒绝清理；
5. 路径必须限制在 Vault 快照目录内；
6. 报告准确记录删除数量、释放字节和跳过项目。
