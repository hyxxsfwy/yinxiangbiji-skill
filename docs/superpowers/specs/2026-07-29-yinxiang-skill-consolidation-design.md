# 印象笔记与 Obsidian Skill 综合升级设计

## 背景

当前仓库已经从单一的印象笔记 API 工具扩展为包含精选导出、多领域编排、正式 Vault 治理、目录重组、逐篇审阅和双向链接维护的综合 Skill。入口 `SKILL.md` 仍把所有流程和一次性任务细节集中在一个文件中；本轮真实重扫又验证了高置信度错域资料需要跨领域归位，而旧逐篇治理规则仍把所有错域资料都送入废纸篓。新增的重分类实现也尚未提供正式命令行接口、统一验收报告和文档入口。

本次升级把历史经验固化为可发现、可执行、可验证的长期能力，不保留具体某一轮任务的日期、关键词或报告文件名。

## 目标

1. 把 `SKILL.md` 收敛为触发条件、任务路由、不可违反的安全边界和完成门禁。
2. 让“本地 Obsidian Vault 治理、精选资料重扫、跨领域归位、索引和双向链接维护”能够直接触发本 Skill。
3. 建立统一决策语义：
   - `keep`：领域正确；
   - `move`：完整正文支持唯一目标领域；
   - `trash`：不属于受管领域或没有保留价值；
   - `pending`：证据不足、并列或存在歧义，保留原位等待人工裁决。
4. 把重分类实现产品化为预览、执行和验证三阶段 CLI，默认解析当前设备的正式 Vault。
5. 所有真实写入都具备全局预检、执行前快照、附件保全、索引重建、受控双向链接和范围化验收。
6. 报告写入 `<vault>/.state/yinxiang-notes/reports/`；仓库忽略 `reviews/`，不把真实 Vault 审阅数据提交到 Git。
7. 用行为测试和文档契约测试防止规则再次漂移。

## 非目标

- 不删除印象笔记账户数据。
- 不自动采用低置信度分类结果。
- 不把关键词相似当作双向链接证据。
- 不重写原始资料正文，只维护 frontmatter、受控链接区块、位置和索引。
- 不在本轮引入外部向量数据库、在线模型服务或新的软件依赖。
- 不追溯清理 Git 历史；只保证当前及后续提交不再跟踪 `reviews/`。

## 信息架构

### 入口 Skill

`SKILL.md` 只保留：

- 适用场景和凭据边界；
- 只读、账户写入、正式 Vault 写入三类任务路由；
- 单领域导出、多领域导出、关键词并集、Vault 重组、精选治理的命令入口；
- 高风险确认词和完成门禁；
- 对详细 reference 的按需引用。

固定日期、固定关键词集合、完整状态目录解释和长篇领域判断规则移出入口。

### 参考文档

新增两个按需加载的 reference：

- `references/export-workflows.md`：单领域、多领域、关键词并集、断点续跑、历史目录和完整性验收。
- `references/selected-materials-governance.md`：重扫、显式决策、跨域移动、废纸篓、附件、双向链接、索引、快照和验证。

现有 `references/obsidian-knowledge-management.md` 继续定义知识库结构、字段、标签和审批边界。README 面向人工使用者保留完整命令和故障排查，但不再把一次性任务伪装成永久契约。

## 精选资料治理架构

### 审计阶段

`reclassify_selected_materials.py audit` 扫描 `30_精选资料/<domain>/YYYY年MM月/*.md`，排除目录索引。分类器只生成建议和证据，不直接写入 Vault。输出包含：

- 当前路径、标题和领域；
- 建议决策、唯一目标领域、分数和命中证据；
- 受控链接校验结果；
- 文档总数和决策统计。

默认报告进入 Vault 状态目录，也允许用 `--output` 指定路径。

### 决策阶段

执行只接受显式 JSON 决策文件。决策文件包含 `moves`、`trash` 和 `links`：

- `moves` 映射源相对路径到目标领域；
- `trash` 列出移入镜像废纸篓的文档；
- `links` 列出经过确认的相关文档，必须双向且每篇不超过三条。

分类器的 `ambiguous` 和 `unclassified` 只能形成待审建议，不能自动转成 `move` 或 `trash`。

### 执行阶段

`apply` 在第一次修改前完成全局预检：

1. Vault、来源、目标领域和目标路径有效；
2. 决策不重复、不重叠；
3. 目标不存在，或附件同名内容一致；
4. 链接两端存在、不会被移入废纸篓，并严格对称；
5. URL 编码附件名先解码后定位；
6. 所有即将变化的 Markdown 和 9 份索引进入 ZIP 快照与 SHA-256 清单。

预检全部通过后，才执行跨域移动或废纸篓镜像复制。跨域移动更新 `domain`，附件复制到目标领域 `_attachments`；同名异内容追加内容哈希并改写引用。废纸篓文档及其本地附件保持可解析。最后只改写 `llmwiki:auto-links` 受控区块，并完整重建全部领域索引。

执行要求固定确认词 `RECLASSIFY_SELECTED_MATERIALS`。

### 验证阶段

范围化验证只检查本轮受管对象，不使用会把正文示例代码、外链或历史隔离区误判为内部链接的全库迁移验证器。验证内容包括：

- 所有移动源消失、目标存在且 frontmatter 领域正确；
- 所有废纸篓源消失、镜像目标存在；
- 变更文档的本地附件引用全部可解析；
- 受控链接存在且双向；
- 每个领域索引集合与符合 `type: 资料`、`domain: 当前领域` 的真实文档集合完全一致；
- 文件名中的方括号使用 URL 编码，显示位置仍保持可读；
- 快照条目、大小和 SHA-256 与清单一致。

只有验证结果 `ok: true` 才能声称完成。

## 兼容策略

`curate_selected_materials.py` 保留，继续支持旧的全覆盖审阅清单。文档明确其 `trash` 仅表示不保留；发现正文属于另一个明确领域时应改用重分类流程的 `move`，不再把“错域”等同于“废弃”。

新 CLI 复用现有 frontmatter、索引和受控链接约定。已有函数接口保持兼容，避免影响已提交测试和外部调用。

## 错误处理与可恢复性

- 预检错误：返回非零，且不创建快照、不修改 Vault。
- 执行中断：保留执行前快照和已写文件，不删除附件源；报告明确为部分完成。
- 验证失败：返回非零并列出具体路径；不得手工修改报告状态。
- 同路径异内容：立即中止，不覆盖任何一方。
- 附件 URL 编码、同名冲突和方括号索引目标均有独立回归测试。

## 测试策略

技能修改遵循 RED—GREEN—REFACTOR：

1. 先增加会暴露现状缺口的测试，包括 CLI 缺失、决策语义冲突、报告默认位置、确认词、范围化验证和入口文档膨胀。
2. 观察测试按预期失败。
3. 以最小实现补齐 CLI、验证函数和文档分层。
4. 运行聚焦测试，再运行完整测试集。
5. 对 Skill 使用压力场景验证：只给出“重扫默认 Vault 并修正错域”的请求时，代理应选择重分类流程，先审计和快照，不把错域资料一律送入废纸篓，也不把低置信度结果自动应用。

完成门禁包括：

- 完整单元测试通过；
- `python -m compileall -q scripts tests` 通过；
- `git diff --check` 通过；
- Skill frontmatter、引用文件和命令均可解析；
- `reviews/` 仍被 Git 忽略；
- 不访问或修改真实 Vault，除非用户另行明确授权执行真实治理任务。
