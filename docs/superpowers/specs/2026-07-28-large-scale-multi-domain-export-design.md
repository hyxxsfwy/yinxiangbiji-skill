# 印象笔记大规模多领域导出设计

## 背景与目标

现有 `export_search_results.py` 适合一次导出一个领域。实际执行 2026 年第二季度的大规模任务时，需要依次运行 AI、Quant、投资理财三个批次，期间出现服务端限流、进程超时、重复正文请求、终端日志过大、历史附件缺失，以及同一 GUID 被多个领域重复收录等问题。

本次优化新增一个面向大规模任务的编排层，在不改变单领域命令用途的前提下，实现一次任务内的全量分页、单次正文获取、唯一领域归属、全局标题去重、断点续跑、限流等待、附件校验、索引重建和机器可读验收报告。

成功标准：

1. 同一 GUID 在一次任务中最多调用一次 `getNote`，限流重试除外。
2. 每篇正文统一比较全部领域，只写入唯一主领域；并列、证据不足或其他未选领域占优时不落盘。
3. 完全一致标题在全部目标领域范围内只保留最新的一个匹配版本。
4. `limit: all` 自动分页到服务端报告的总数，不再依赖人工估算 `max-per-keyword`。
5. 断点状态能够识别领域规则变化；旧的“已导出”文件不能绕过新规则。
6. API 限流在配置预算内自动等待并继续，超出预算时保存状态后退出。
7. 成功退出前，目录索引、创建时间范围、附件引用、领域内和跨领域重复项全部通过验证。

## 方案边界

保留现有 `export_search_results.py`，用于小批量、单领域、交互式导出。新增 `export_multi_domain.py`，用于两个及以上领域、关键词重叠或候选数较大的任务。

本次不建立长期数据库，不把完整 ENML 或附件缓存进 Git 仓库，也不改变印象笔记账户数据。运行状态和报告位于已忽略的 `.state/`，只保存 GUID、时间戳、判定结果、规则指纹、路径和统计信息。

## 任务清单

新命令接收 JSON 任务文件：

```json
{
  "since": "2026-04-01",
  "until": "2026-07-01",
  "vault": "D:\\OneDrive\\文档\\@_Obsidian",
  "domains": {
    "AI": {
      "keywords": ["AI", "人工智能", "LLM", "Agent"]
    },
    "Quant": {
      "keywords": ["量化", "量化交易", "Quant"]
    },
    "投资理财": {
      "keywords": ["金融", "基金", "ETF", "比特币", "BTC"]
    }
  }
}
```

领域目标固定派生为 `<vault>/30_精选资料/<domain>`，任务文件不能把内容写到其他生命周期目录。日期使用左闭右开区间：`since` 包含当日，`until` 不包含当日。

命令形态：

```powershell
python scripts/export_multi_domain.py `
  --job ".state/jobs/2026-q2.json" `
  --rate-limit-mode wait `
  --max-rate-limit-wait 3600
```

默认输出汇总。`--verbose` 才逐篇打印拒绝原因；完整结果始终写入 JSON 报告。

## 核心数据流

### 1. 任务规范化与规则指纹

读取任务文件后，校验日期、领域、关键词、vault 结构和目标目录。对排序后的 `DOMAIN_PROFILES`、判定算法版本和正文清洗版本生成 SHA-256 规则指纹。

任务 ID 由规范化后的 vault、日期范围和领域关键词生成。状态文件为 `.state/multi-export-<task-id>.json`，报告写入 `.state/reports/`。

### 2. 全量元数据搜索

每个领域的每个关键词使用相同日期过滤条件分页搜索。分页持续到已拉取数等于 `totalNotes`；任何关键词未拉全时，任务在拉取正文前失败，不得把不完整结果描述为“全部”。

全部搜索批次按 GUID 合并，保留候选命中的领域和关键词。候选按 `updated`、`created`、GUID 倒序排列，从而让最新的同标题剪藏先接受审核。

### 3. 流式正文审核

逐个候选调用一次 `getNote(..., withContent=True, withResourcesData=True)`。正文只在当前循环中存在，不积累完整 Note 或资源对象。

对正文计算所有已知领域得分：

- 唯一最高且满足证据门槛的领域是主领域。
- 主领域不在任务声明的领域中时拒绝。
- 多领域并列、证据不足或无法确定时拒绝。

候选通过后，再进行全局完全一致标题去重。由于候选已按新旧排序，首个通过正文门禁的版本成为规范版本，后续同标题候选记录为重复项且不写入。

### 4. 可验证的断点续跑

每处理一篇候选便原子更新状态：

```json
{
  "guid": {
    "updated": 1780000000,
    "policy_hash": "...",
    "outcome": "accepted",
    "primary_domain": "AI",
    "title": "...",
    "path": "30_精选资料/AI/2026年05月/文章.md"
  }
}
```

快速跳过必须同时满足：

1. GUID 与 `updated` 未变化；
2. `policy_hash` 与当前规则一致；
3. 状态中的主领域与文件 frontmatter 一致；
4. Markdown 文件存在；
5. 文件引用的本地附件全部存在。

任一条件不满足都重新审核。旧状态没有规则指纹时不能直接跳过；可先读取现有 Markdown 正文完成一次本地重审，附件不完整时再从 API 补拉。

### 5. 限流和网络错误

共享运行时增加可测试的限流重试器。捕获印象笔记 `EDAMSystemException` 且错误码为限流时：

- `stop` 模式：保存状态并立即退出；
- `wait` 模式：当服务端建议等待时间未超过剩余预算时，输出一次等待摘要，等待后重试同一操作；
- 超出预算：保存状态并以专用退出码结束。

HTTP 请求继续使用 60 秒超时。非限流异常不做无限重试，保留已完成状态并返回失败。

### 6. 写入、附件和索引

只有主领域判定和全局标题去重都通过后，才调用现有 Markdown/附件转换函数。文章继续按印象笔记 `created` 归入 `YYYY年MM月/`，附件保存在领域根目录 `_attachments/`。

同一任务产生的新内容不会跨领域重复。对于任务范围内发现的历史跨领域重复：

- 按当前规则选择规范文件；
- 在删除完全重复的 Markdown 副本前生成清单和 ZIP 快照；
- 不删除共享附件；
- 重新构建受影响领域的 `目录索引.md`。

若无法唯一决定主领域，只报告冲突并使验收失败，不自动删除。

### 7. 验收报告

结束阶段生成 JSON 报告，并在终端输出简表。报告至少包括：

- 每个关键词的服务端总数和实际拉取数；
- GUID 候选数、正文请求数、状态跳过数；
- 按领域和创建月份统计的新增、已有、拒绝、重复数量；
- 限流次数和累计等待时间；
- 索引条目数、缺失索引目标；
- 图片与附件引用数、缺失附件；
- 领域内和跨领域重复标题/GUID；
- 日期越界、frontmatter 解析失败和无法确定主领域的列表。

只有所有硬性检查为零错误时返回成功。报告中的文章总数必须明确区分“本任务日期范围内”与“目标目录现存总数”。

## 组件划分

### `scripts/runtime.py`

提供限流识别和有预算重试，不包含导出业务。

### `scripts/export_search_results.py`

继续提供领域词表、正文抽取、打分、单篇写入等基础能力。新增稳定的规则指纹和“计算唯一主领域”接口，单领域命令同步使用新状态契约。

### `scripts/export_multi_domain.py`

负责读取任务、全量搜索、GUID 合并、流式审核、全局标题去重、断点状态、领域写入和最终验收。该模块只编排，不复制 ENML 转换代码。

### `scripts/export_integrity.py`

负责扫描目标领域、校验索引与附件、发现跨领域重复，并生成结构化结果。修复动作与只读检查分离，便于单元测试和独立运行。

## 错误处理与安全

- 任务文件、状态文件和报告均不得包含 Token。
- 真实账户只执行读取；所有写操作只发生在用户指定的本地 vault。
- 写入状态使用临时文件加原子替换，防止中断产生半个 JSON。
- 删除历史重复副本前必须创建快照；路径解析后必须确认仍位于 `<vault>/30_精选资料/`。
- 索引或附件验证失败时返回非零，不输出“导入完成”。

## 测试设计

代码严格采用 RED-GREEN-REFACTOR：

1. 全量分页测试：服务端总数超过旧上限时仍拉取全部元数据。
2. 单次正文测试：同一 GUID 命中多个领域关键词仍只调用一次 `getNote`。
3. 唯一主领域测试：主领域、并列、任务外领域占优三种结果。
4. 全局标题去重测试：多个领域中同标题只保留最新匹配版本。
5. 规则指纹测试：规则未变可跳过，规则变化必须重新审核。
6. 附件完整性测试：状态有效但附件缺失时不得快速跳过。
7. 限流测试：预算内等待后成功、`stop` 模式退出、超预算退出。
8. 日志测试：默认只输出汇总，详细拒绝项进入报告。
9. 验收测试：索引缺项、缺图、越界和跨领域重复均使任务失败。
10. 端到端假客户端测试：一个任务完成三个领域的写入、归档、索引和报告。

Skill 文档按 `writing-skills` 进行行为测试：先让不读取新规则的子代理规划大规模导入，记录其是否仍选择三个独立命令、人工核对上限和事后去重；更新 Skill 后复测，要求其主动选择多领域命令并把验收作为成功条件。
