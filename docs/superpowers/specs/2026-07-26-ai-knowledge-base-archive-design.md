# AI 知识库月度归档与目录索引设计

## 目标

将印象笔记搜索结果稳定转存为按创建月份归档的 Obsidian 知识库，并在知识库根目录维护一个普通 Markdown 目录索引。转存过程同时消除标题完全一致的重复剪藏，确保同一标题在知识库中只保留一篇。

## 适用范围

- 目标目录为 `AI相关知识库` 或用户通过 `--target` 指定的同类知识库根目录。
- 本设计作用于 `scripts/export_search_results.py` 的搜索结果导出流程。
- 现有根目录 Markdown 文章在首次运行新版导出流程时一并迁移。
- 不修改印象笔记账户中的原始笔记，不清理可能被其他文章引用的附件。
- `sync_to_obsidian.py` 的整库、分笔记本同步目录结构保持不变。

## 已确认规则

### 月度归档

- 归档月份严格使用笔记的 `created` 时间，不使用 `updated`。
- 时间戳按当前运行环境的本地时区转换，目录名称固定为 `YYYY年MM月`，例如 `2026年07月`。
- Markdown 文章写入 `<知识库根目录>/<YYYY年MM月>/<标题>.md`。
- 知识库根目录只保留 `目录索引.md`、`_attachments/` 等公共资源，不再直接存放文章。

### 附件布局

- 图片和其他附件继续统一存放在 `<知识库根目录>/_attachments/`。
- 月度目录中的 Markdown 使用 `../_attachments/<文件名>` 引用附件。
- 迁移现有根目录文章时，把正文中的 `_attachments/` 相对引用改写为 `../_attachments/`。
- 不移动或删除现有附件，避免破坏其他文章引用。

### 同标题去重

- 先按 GUID 合并同一笔记的重复搜索命中，再按标题去重。
- “标题完全一致”定义为去除首尾空白后 Unicode 字符串完全相同，区分大小写，不做模糊匹配。
- 同标题候选保留 `updated` 最大的一篇；若 `updated` 相同，则保留 `created` 最大的一篇；仍相同时以 GUID 字符串排序保证结果确定。
- 去重发生在截取前 N 篇之前，因此 `--limit 3` 表示最多导出 3 个不同标题。
- 新版导出成功后，知识库内同标题的旧版本 Markdown 会被移除，只保留本次选中的版本。附件不随旧版本删除。

## 目录索引

根目录固定生成 `目录索引.md`。索引是完整重建的确定性文件，不依赖 Dataview 或其他 Obsidian 插件。

索引结构如下：

```markdown
# AI 相关知识库目录

## 2026年07月

- [文章标题](2026%E5%B9%B407%E6%9C%88/%E6%96%87%E7%AB%A0%E6%A0%87%E9%A2%98.md)
  - 位置：`2026年07月/文章标题.md`
  - 简介：首段有效正文形成的第一句话。本文目录包括“章节一”“章节二”“章节三”等内容。
```

- 月份按倒序排列，最近月份在前。
- 同一月份内按笔记创建时间倒序排列；创建时间相同时按标题排序。
- 文档链接使用相对路径并进行 URL 编码，位置字段保留可读的中文相对路径。
- 索引扫描月度目录中的 Markdown 文件生成，不把 `目录索引.md` 自身列入目录。

## 简介生成

简介由“首段有效正文”和“目录大纲”综合形成，保持一到两句话，不调用外部大模型。

### 首段有效正文

从已简化的 Markdown 正文依次扫描，跳过以下内容：

- YAML frontmatter 和文档一级标题；
- `原文链接`、作者署名、公众号关注提示等来源元信息；
- 空行、图片、表格、代码块、分隔线和纯标题行；
- 过短且不能独立表达文章主题的装饰性文本。

选取第一段完整正文，优先保留第一句；若没有中文或英文句末标点，则在不破坏 Markdown 链接的前提下限制长度。

### 目录大纲

- 收集正文中的二级和三级标题。
- 去除章节编号后保留最多四个不同标题。
- 有大纲时生成第二句话，例如：`本文目录包括“注意力机制”“冲突规则”“工程化解法”等内容。`
- 没有大纲时只使用首段有效正文。
- 纯图片笔记或没有有效正文时，使用：`该笔记主要以图片形式呈现“<标题>”相关内容。`

## 迁移与幂等性

1. 导出选中的去重结果到对应月度目录。
2. 扫描知识库根目录已有的 Markdown 文章，读取 frontmatter 中的 `created` 并迁移到相应月份。
3. 若月度目录已有相同 `source_guid` 的文件，保留新导出的文件并删除根目录旧副本。
4. 清理同标题的旧版本 Markdown，只保留按去重规则选中的文件。
5. 重新扫描月度目录并原子更新 `目录索引.md`。

重复运行相同命令不得产生重复文章、GUID 后缀副本、重复索引项或重复附件引用。无法解析 `created` 的非标准 Markdown 不自动猜测日期，保留在原位置并输出明确警告。

## 代码边界

### `scripts/knowledge_base.py`

新增知识库归档模块，负责：

- `month_folder_name(created)`：生成 `YYYY年MM月`；
- `extract_note_metadata(markdown_path)`：读取索引所需的标题、创建时间和 GUID；
- `build_note_summary(markdown_text, title)`：生成正文加大纲简介；
- `archive_root_notes(root)`：迁移现有根目录文章并改写附件路径；
- `remove_duplicate_title_files(root, selected_notes)`：清理同标题旧版本；
- `write_knowledge_base_index(root)`：完整重建目录索引。

### `scripts/export_search_results.py`

- 搜索结果在限制数量前按标题去重。
- 附件仍写入知识库根目录。
- 单篇笔记根据 `created` 直接写入月度目录。
- 全部导出成功后执行根目录迁移、同标题旧版本清理和索引重建。

### `scripts/sync_to_obsidian.py`

仅给已有附件链接辅助函数增加可选相对路径前缀，默认行为不变，避免影响整库同步。

### `SKILL.md`

在“搜索并导出”工作流中明确：

- 按 `created` 使用 `YYYY年MM月` 目录；
- 标题完全一致时按 `updated`、`created`、GUID 的顺序保留一篇；
- 根目录必须生成 `目录索引.md`；
- 简介必须综合首段有效正文和二、三级目录标题；
- 完成后检查文章位置、索引条目和附件相对路径。

## 错误处理

- 任一选中笔记导出失败时，不执行旧版本清理，避免先删除可用文件。
- 单篇迁移失败时记录文件路径和原因，继续处理其他文件，最终返回失败状态。
- 索引先写入同目录临时文件，成功后替换正式文件，避免中断时留下半份索引。
- 目标文件冲突且 GUID 不同、标题也不属于已确认的重复组时，沿用现有 GUID 后缀规则，不覆盖无关文章。

## 测试与验收

自动化测试必须覆盖：

1. 创建时间正确映射为 `YYYY年MM月`。
2. 导出文章位于月度目录，图片链接指向根目录 `_attachments/`。
3. 现有根目录文章迁移后链接正确且原文件消失。
4. 同标题候选按 `updated`、`created`、GUID 顺序保留。
5. 去重在 `limit` 之前发生，结果标题互不重复。
6. 简介同时包含有效正文信息和最多四个目录标题。
7. 纯图片笔记生成可读的回退简介。
8. 索引包含可点击位置、可读位置和简介，月份与文章顺序正确。
9. 重复运行不会产生重复文件或重复索引项。
10. 现有完整测试套件继续通过。

实际知识库验收要求：

- 当前 5 篇根目录文章全部位于 `2026年07月/`。
- 根目录生成 `目录索引.md`，包含 5 个唯一标题及对应简介。
- 根目录不再残留文章 Markdown。
- 所有 Markdown 图片引用均能解析到存在的附件文件。
