# Obsidian LLM Wiki 统一目录与迁移设计

> 本设计中的生命周期目录编号已被
> [Obsidian 生命周期目录重新编号设计](2026-07-27-obsidian-lifecycle-directory-renumbering-design.md)
> 取代；业务分层、领域和 LLM Wiki 治理规则仍然有效。

## 1. 背景与目标

当前印象笔记账户共有 38 个笔记本、49,270 篇笔记和 208 个标签。笔记本分为
`0.默认`、`1.缓存`、`2.专题`、`3.归档`、`4.共享`以及未分组内容；标签最大
嵌套深度为四层，根标签为 `$主题`、`$任务`、`$状态`和 `_Apps`。原结构同时
混合了采集来源、年份归档、主题、任务优先级和个人状态，不适合直接复制到
Obsidian。

本次整理不全量迁移印象笔记历史库存。历史剪藏继续留在印象笔记，Obsidian
只接收已经选定或今后按规则选定的持续有用内容。现有 Obsidian vault 位于：

```text
D:\OneDrive\文档\@_Obsidian
```

vault 当前包含：

- `AI相关知识库`：5 篇 Markdown 文章、1 份目录索引及本地图片附件；
- `Quant相关知识库`：1 篇公众号原文；
- `HYXX个人知识库`：1 篇个人编写的 Codex CLI 使用技巧，以及一份嵌套的
  `.obsidian` 配置。

本设计的目标是把这三个目录迁入一套统一、精简、可长期人工维护，并为后续
AI 半自动整理、双向链接和知识地图维护预留明确边界的 LLM Wiki。整个
`@_Obsidian` vault 是 LLM Wiki，不能再把某个系统子目录命名为 `LLM Wiki`。

## 2. 核心组织原则

文件夹表示内容所处的生命周期，Properties 表示内容性质，标签表达跨目录
主题，内部链接表达知识关系。来源、领域、类型、状态和主题必须分开表达。

内容只允许有一个原始文件位置：

- 项目内容放入 `10_项目`；
- 经人工理解、验证或重写后形成的知识放入 `20_知识笔记`；
- 仍值得引用的原文、剪藏、PDF 和图片放入 `30_精选资料`；
- 已完成且不再活跃的过程材料放入 `99_归档`。

精选资料完成提炼后仍留在 `30_精选资料`，只把 `status` 改为 `归档`。提炼
得到的结论另建为短小的知识笔记，通过内部链接引用原始资料，不复制原文。
项目文件同样只引用知识笔记和精选资料，不另存副本。

`目录索引.md`，因为资料索引需要由导出脚本按领域单独重建。

| `AI相关知识库`中的 5 篇文章、索引和附件 | `30_精选资料/AI/` | 印象笔记原文或网页剪藏 |

文章中的 `../_attachments/`链接迁移后仍指向同一领域目录下的附件。

三个旧知识库目录只在文件数量、哈希、索引和链接检查全部通过后删除。

## 5. Properties 契约

日常人工维护的核心字段为：

```yaml
type:
domain:
status:
tags: []
```

允许值为：

- `type`：`资料`、`知识`、`索引`、`模板`；
- `domain`：`AI`、`Quant`、`软件工程`、`投资理财`、`个人成长`；
- `status`：`待处理`、`待提炼`、`常青`、`归档`；
- `tags`：最多三个受控主题标签。

LLM Wiki 管理字段为：

```yaml
uid:
summary:
aliases: []
review_status: pending
reviewed_by:
reviewed_at:
llm_policy: standard
```

迁移后的 AI 剪藏保留原有 `created`、`updated`、`source`、`source_guid`和
`notebook`，并补充：

```yaml
type: 资料
domain: AI
status: 待提炼
review_status: pending
llm_policy: strict
```

只有三篇明确涉及 Agent 的文章使用 `主题/Agent`；其他文章使用空标签。

Quant 原文补充：

```yaml
type: 资料
domain: Quant
status: 待提炼
created: 2026-06-12
source: 微信
source_url: "https://mp.weixin.qq.com/s?__biz=Mzg2MzAwNzM0NQ==&mid=2247494007&idx=1&sn=cc89b84a7928baddf755d58e867cc99a&chksm=cfa518120a5d72b4845ecac9547a37b2ab716be7ac6831e782cf6bb4c9f4a75ea3ea15c44f79#rd"
tags: []
review_status: pending
llm_policy: strict
```

Codex CLI 知识笔记补充：

```yaml
type: 知识
domain: 软件工程
status: 常青
created: 2026-07-04
tags: []
review_status: human-approved
llm_policy: standard
```

## 6. 标签精简与旧标签映射

Obsidian 只使用两层主题标签：

```text
主题/<主题名>
```

领域已经由 `domain`表达，不能再同时使用 `AI`、`软件工程`等领域标签。标签
数量最多三个，不是必须填满；没有必要时保持 `tags: []`。

旧标签按以下规则映射：

| 旧标签 | 新表达 |
| --- | --- |
| `_Apps/微信`、Twitter、微博等 | `source`属性 |
| `$任务/待阅读`及其优先级 | `status: 待提炼` |
| `$任务/待处理` | `status: 待处理` |
| `$状态`下的个人状态 | 不迁移 |
| `$主题/$网摘`、`$资源` | `type: 资料` |
| `$主题/$模板` | `type: 模板`，进入 `90_系统/模板` |
| `$主题/CS_IT` | `domain: 软件工程` |
| `CS_IT/ML&AI` | `domain: AI` |
| `$管理/理财` | `domain: 投资理财` |
| `$管理/理财/量化交易` | `domain: Quant` |
| `$币圈`、区块链、Bitcoin、Web3.0 | `domain: 投资理财`，必要时使用 `主题/区块链` |
| `$个人`、`$学习` | 默认 `domain: 个人成长`，再按正文纠正 |

永久标签必须同时满足：预计至少被三篇笔记使用；不是来源、领域、类型或状态；
不能用明确内部链接代替；与已有标签不是同义词；名称可以长期稳定使用。

迁移后首个正式主题只有：

```text
主题/Agent
```

`主题/OpenAI`、`主题/AI编程`、`主题/AI安全`、`主题/量化研究`、
`主题/Codex`、`主题/PKM`、`主题/信息安全`和`主题/区块链`先记录为候选，
达到复用条件后再启用。

## 7. 首页与索引

### 7.1 首页

`00_首页.md`是整个 HYXX LLM Wiki 的总入口，只提供工作台、知识、精选资料和
系统治理导航，不罗列全部文件。

### 7.2 项目目录

`10_项目/目录索引.md`文件头必须说明：该目录只存放有明确目标、交付物和结束
条件的工作项目；后续按项目名称创建目录；项目结束后，通用认识提炼为知识
笔记，原始资料转入精选资料，过程材料归档。AI 可以补充项目状态摘要，但不能
自动移动、归档或删除项目。

### 7.3 知识笔记目录

`20_知识笔记/目录索引.md`提供完整且可重建的知识笔记清单。文件头必须说明：

- 扫描 `20_知识笔记`下全部 `type: 知识`文件；
- 按 `domain`分组；
- 每个领域按 `updated`倒序排列；
- 每项包含链接、摘要、状态和更新时间；
- 本文件可由脚本或 AI 完整重建，不保存人工评论；
- 不收录精选资料和项目文件。

### 7.4 知识地图

`20_知识笔记/知识地图.md`展示经过选择的核心知识与关系，不承担完整文件清单。
文件头必须说明：

- 人工维护核心概念、关键入口和跨领域关系；
- AI 只能修改 `<!-- llmwiki:auto:start -->`与
  `<!-- llmwiki:auto:end -->`之间的区域；
- 每篇知识笔记只建立三至七个高价值链接；
- 仅关键词相同不足以建立关系；
- 同名或多候选目标必须完成链接消歧。

### 7.5 精选资料索引

`30_精选资料/<领域>/目录索引.md`只收录本领域的 `type: 资料`文件，按创建
月份和创建时间倒序排列。每项包含文档链接、相对位置和一至两句话简介；简介
由首段有效正文和最多四个二、三级目录标题综合形成。文件头必须明确：索引可由
导出脚本完整重建，不得存放人工评论。

## 8. 知识库治理

`90_系统/知识库治理`不代表 LLM Wiki 本身，只保存整个 vault 的治理资产：

- `管理规则.md`：人工与 AI 共同遵守的迁移、标签、链接、审核和回滚规则；
- `主题词表.md`：正式主题、候选主题、同义合并以及启停原因；
- `别名词典.md`：规范名称、同义词、旧名称和英文缩写；
- `审核队列`：不能自动审批的提案；
- `审核日志`：规则版本、证据、执行者和审批结果；
- `变更快照`：AI 自动变更前的可回滚状态。

原始资料正文只读。AI 可以生成摘要、属性和链接建议，只能直接维护知识地图的
自动区域。创建永久标签、修改人工结论、合并、移动、重命名、删除、提升常青
状态以及修改知识地图人工区必须人工审批。

## 9. 迁移与回滚

迁移采用“快照、复制、补充元数据、验证、删除旧文件”的顺序。不得直接原地
移动。

`90_系统/迁移记录`生成：

```text
2026-07-27-迁移说明.md
2026-07-27-文件清单.json
2026-07-27-链接检查.md
2026-07-27-迁移前备份.zip
```

备份 ZIP 保存三个旧知识库目录的完整内容。文件清单记录原始路径、目标路径、
文件大小、SHA-256、迁移结果和链接检查结果。

迁移后检查：

- 所有 Markdown 图片和普通相对链接；
- URL 解码后的本地目标是否存在；
- 图片目标是否位于配置的 vault 内；
- 是否仍有链接指向三个旧目录；
- Markdown 文件和附件的数量；
- 未修改文件的 SHA-256；
- 新首页和索引中的内部链接。

当前预扫描发现 8 个 Markdown 文件、50 个图片引用和 15 个普通 Markdown
链接，没有失效的本地链接，也没有现成的 Obsidian Wiki 链接。迁移不修改外部
HTTP 链接。

只有在目标文件、哈希、索引、附件和链接检查全部通过，且备份和迁移清单已经
生成后，才能删除三个旧知识库目录。

## 10. Skill 仓库同步

迁移完成后同步更新 `yinxiang-notes` Skill：

- 把知识管理参考文档的目录编号改为 `10_项目`、`20_知识笔记`和
  `30_精选资料`；
- 明确整个 vault 是 LLM Wiki；
- 把治理资产路径改为 `90_系统/知识库治理`；
- 记录知识目录索引、知识地图和分领域资料索引的不同职责；
- 保持历史剪藏留在印象笔记、按需精选迁移和人工审批边界不变；
- 将本地 `.env`的 `OBSIDIAN_VAULT_PATH`配置为
  `D:\OneDrive\文档\@_Obsidian`；
- 后续 AI 精选导出目标统一使用
  `D:\OneDrive\文档\@_Obsidian\30_精选资料\AI`。

## 11. 验收标准

实施完成必须同时满足：

1. 新目录树全部存在；
2. 三个旧知识库目录已经清理；
3. 迁移前已有的 8 个 Markdown 文件均有唯一的新位置；
4. 原有附件数量和哈希一致；
5. 迁移前已有的 50 个图片引用均已处理，本地图片目标全部存在，外部图片 URL
   保持不变；
6. 所有本地 Markdown 链接有效；
7. `00_首页.md`中的入口全部可达；
8. 各索引文件的功能和构建规则写在文件头；
9. 只有 `主题/Agent`作为首个正式主题标签；
10. 迁移快照、文件清单和链接检查报告完整；
11. Skill 仓库规则与实际 vault 结构一致；
12. 全过程不修改印象笔记账户数据。
